# Countryballs — детская браузерная игра-песочница

**Статус:** технически проработанный mini-GDD / спецификация MVP для передачи в разработку  
**Версия документа:** 1.0 · 18 ноября 2026 г.  
**Язык интерфейса:** только русский  
**Формат поставки:** PWA (Progressive Web App), без привязки к Android  
**Целевая аудитория:** ребёнок примерно 6 лет, умеющий пользоваться сенсорным интерфейсом, но ещё не уверенно читающий  
**Приоритет:** создать работающую, приятную игрушку, а не универсальный графический редактор

> **Короткое описание.** Ребёнок выбирает флаг страны из единой прокручиваемой галереи, слышит её название по-русски, создаёт Countryball со слоями глаз, эмоций и аксессуаров, затем размещает несколько созданных персонажей на сцене и разыгрывает короткие весёлые истории с простыми анимациями и звуками.

### Уточнения для первой семейной версии

При расхождениях с исходной дорожной картой ниже для первой версии действуют эти договорённости:

- Браузерная SPA/PWA со статическими ресурсами, без бэкенда и внешних БД. На этом устройстве автоматически восстанавливаются готовая коллекция и парк.
- Сначала **полная цепочка**, а не полный объём каталога: флаг и голос → мордочка и аксессуары → «Готово» прямо в парк → приветствие с подсвеченным приятелем. С главной можно сразу играть с двумя готовыми героями.
- Единый стартовый набор из 16 флагов: Казахстан, Россия, США (озвучка «Соединённые Штаты Америки»), Япония, Германия, Бразилия, Беларусь, Украина, Франция, Италия, Испания, Иран, Англия (красный крест на белом, не флаг Великобритании), Южная Корея, Турция, Китай. При расширении до 195 государств Англия остаётся дополнительной плиткой.
- Одна палитра готовых мордочек. Рисования с нуля нет. **Кошачьи ушки** (одна пара) и **кошачий хвостик** — независимые предметы: добавление, перемещение, масштабирование, поворот и снятие любого из них не затрагивают другой. Доступны всем странам, допускаются дубликаты.
- Проверить эту цепочку с ребёнком до расширения каталога, сцен и действий.

## 1. Цель и границы проекта

### 1.1. Основной игровой цикл

1. Открыть **Мастерскую**.
2. Выбрать флаг в **едином каталоге флагов**. Название страны произносится вслух при касании плитки.
3. Настроить глаза / выражение лица и добавить аксессуары.
4. Нажать **«Готово»**: персонаж появляется в коллекции текущей игровой сессии.
5. Открыть **Сцену**, выбрать фон, разместить на ней несколько Countryballs.
6. Двигать, поворачивать и масштабировать их, менять эмоции, запускать индивидуальные и парные взаимодействия.
7. Продолжать свободно играть; нет обязательных заданий, поражения, очков или сюжета.

### 1.2. Продуктовые принципы

- **Не нужно уметь читать.** Названия стран подписаны по-русски для узнавания, но основные действия доступны по крупным понятным иконкам, с визуальными реакциями и звуком.
- **Быстрый результат.** Важное действие должно происходить за 1–3 касания; взаимодействие двух персонажей — максимум 3 касания (выбор первого → действие → выбор второго).
- **Сначала игрушка, потом система.** Никакой карты мира, политической игры, стратегии, уровней, опыта, прокачки и инвентаря.
- **Свободная игра.** Персонажи не живут сами по себе и не инициируют социальные действия; допускается только лёгкая фоновая idle-анимация.
- **Не привязываем игру к одной платформе.** Разрабатывается обычное веб-приложение, устанавливаемое как PWA; управление мышью и пальцами.
- **Сохранение пользовательских персонажей и сцен — отдельный поздний этап.** Для MVP достаточно состояния текущей открытой сессии без персистентности.
- **Без рекламы, регистрации, чатов, внешних ссылок внутри детского игрового пути и пользовательского контента из сети.**

### 1.3. Что намеренно не делаем в MVP

Карта мира, бои, деньги, инвентарь, квесты, соревнования, обучение чтению, сложная физика, сервер, синхронизация, LLM, мультиплеер, автопилот поведения персонажей, редактор собственных изображений, экспорт видео, запись сцен, сохранение/загрузка проектов.

## 2. Технологическая основа

### 2.1. Рекомендуемый стек

| Область | Решение | Причина |
|---|---|---|
| Сборка | Vite + TypeScript | Простой быстрый веб-проект |
| UI | React | Меню, галерея флагов, вкладки, адаптивная вёрстка |
| Сцена и редактор | `konva` + `react-konva` | Группы, Canvas, маски, перетаскивание, трансформации, анимации |
| Стили | CSS / CSS Modules | Не требуется тяжёлая UI-библиотека |
| Глобальное состояние | React state или Zustand | Простая модель персонажей и сцен; начать с минимального решения |
| Звуки | HTMLAudioElement / Web Audio API | Короткие SFX и озвучивание названий |
| PWA | `vite-plugin-pwa` + Workbox | Manifest, service worker и кеширование ресурсов |
| Данные | Локальные JSON/TS-модули | Без API и сервера на MVP |
| Тесты | Vitest + Testing Library + Playwright | Правила каталога, модели данных, основные маршруты UI |

**Почему не Phaser на старте:** основная сложность этой игры — редактор с вложенными объектами и жестами, а не игровой цикл/физика. Konva хорошо соответствует задаче. Это архитектурный выбор, не запрет на замену движка в будущем.

**Важная граница:** DOM/React отвечает за прокручиваемые списки, крупные кнопки, подписи и фокус ввода; Konva — за холст мастерской и игровую сцену. **Не рисовать всю галерею флагов внутри Canvas:** стандартный DOM-скролл на разных устройствах надёжнее, проще и доступнее.

### 2.2. Подтверждённые возможности и ограничения

- `Konva.Group` позволяет объединять и трансформировать несколько узлов как один объект.
- `clipFunc` позволяет обрезать флаг по кругу.
- `Transformer` позволяет менять размер и поворот; его изменения `scaleX/scaleY` требуется корректно переносить в модель.
- Поддержка жестов двумя пальцами возможна, но **их интерпретацию нужно реализовать/проверить**, включая разделение «вращаем персонажа» и «прокручиваем/масштабируем сцену».
- Web Speech API может произносить текст, но набор русских голосов зависит от ОС/браузера, а некоторые голоса могут требовать интернет. Нельзя гарантировать одинаковую озвучку и автономность через системный синтез.
- PWA можно установить в поддерживающих браузерах; способ установки зависит от браузера/ОС. Для рабочего офлайн-режима нужен service worker, кеширующий все необходимые ресурсы.
- Браузеры ограничивают автоматическое воспроизведение звука до пользовательского взаимодействия. Озвучка флага запускается **непосредственно по нажатию**, а не при загрузке страницы.

## 3. Навигация и экраны

```text
Главный экран
  ├── Мастерская
  │     ├── Каталог флагов (единая прокрутка)
  │     ├── Глаза и выражение
  │     ├── Аксессуары
  │     └── Готово → коллекция текущей сессии
  └── Сцена
        ├── Выбор фона
        ├── Добавление готовых Countryballs
        ├── Размещение и трансформация
        └── Эмоции / действия / парные взаимодействия
```

На старте желательно показать две большие иллюстрированные кнопки: **«Создать»** (иконка Countryball с кисточкой) и **«Играть»** (несколько шариков на фоне). Если коллекция пуста, «Играть» предлагает создать персонажа, а не выдаёт ошибку.

### 3.1. Экран каталога флагов

**Цель:** выбрать страну одним нажатием, получить яркую визуальную и голосовую обратную связь.

- Одна **непрерывная** прокручиваемая сетка всех стран. **Никакого обязательного выбора континента, региона или алфавитной группы.**
- На плитке изображение флага (не эмодзи) и **подпись на русском языке снизу**.
- Текущий выбор выделен рамкой; нажатие сразу применяет флаг к предпросмотру Countryball.
- **При каждом явном нажатии на плитку** произносится русское название страны. Нажатие на уже выбранный флаг повторяет озвучку.
- Дополнительная крупная кнопка 🔊 рядом с предпросмотром повторяет название, не меняя выбора.
- Прокрутка сама по себе ничего не озвучивает, чтобы не возникала звуковая какофония.
- Кнопка **«Далее»** переводит к редактированию; можно вернуться к флагам без сброса аксессуаров.
- Необязательный поиск на русском можно оставить как второстепенный элемент для взрослого. Ребёнок должен обходиться без поиска.

**Начальное наполнение:** целевой базовый каталог из **195 государств**: 193 государства — члена ООН и 2 государства-наблюдателя. Это продуктовый набор, а не число всех возможных флагов. В дальнейшем можно подключить территории и иные флаги отдельными наборами, не ломая единый список. **Не считать, что ISO 3166-1 совпадает с перечнем 195 один к одному:** требуется явный курируемый список и соответствие кода/флага/русского названия/произношения.

**Порядок:** русский алфавит по `nameRu`, через `Intl.Collator('ru')` или заранее проверенную сортировку, без визуального деления на континенты. Удерживать позицию прокрутки при возврате к каталогу.

**Адаптивная сетка (проектные ориентиры, уточняются по прототипу):**

| Экран | Колонок | Особенности |
|---|---:|---|
| Узкий телефон | 3 | Длинные названия до 2 строк |
| Планшет вертикально | 4–5 | Крупные плитки и подписи |
| Планшет горизонтально | 6–8 | Широкая зона прокрутки, живой предпросмотр сбоку |
| Компьютер | 6–10 | Скролл колесом мыши и курсор |

Не использовать жёсткую геометрию по типу устройства: количество колонок вычислять от доступной ширины. Минимальный размер интерактивной области — 48×48 CSS px, целевой — около 56 px и больше. Высоту плитки подбирать так, чтобы подпись не обрезалась.

**Упрощённая схема широкого экрана:**

```text
┌────────────────────────────────────────────────────────────┐
│  ←                 ВЫБЕРИ СТРАНУ                         🔊  │
├─────────────────────────────────┬──────────────────────────┤
│  [ 🇷🇺 ] [ 🇯🇵 ] [ 🇨🇳 ] [ 🇧🇷 ]  │                          │
│ Россия  Япония  Китай  Бразилия │      ПРЕДПРОСМОТР        │
│                                 │         (шарик)         │
│  [ 🇩🇪 ] [ 🇫🇷 ] [ 🇰🇿 ] [ 🇨🇦 ]  │                          │
│ Германия Франция Казахстан ...  │       «Япония»          │
│                                 │                          │
│    ↕ ПРОКРУЧИВАЕМ ВСЕ ФЛАГИ     │        [ ДАЛЕЕ ]         │
└─────────────────────────────────┴──────────────────────────┘
```

*Эмодзи выше — только обозначение мест в схеме. В приложении нужны локально поставляемые флаги SVG/PNG с проверенными правами использования.*

### 3.2. Экран мастерской

В центре крупный Countryball на нейтральном фоне. Под ним или сбоку — пиктографические вкладки:

1. **Флаг** — повторно открыть общий каталог.
2. **Глаза** — выбрать из набора графических шаблонов (обычные, радостные, сердитые, удивлённые, хитрые, сонные).
3. **Выражение** — смех, улыбка, грусть, сердитость, удивление, смущение. Набор выражений должен управлять согласованной комбинацией глаз и рта, а не заставлять ребёнка настраивать каждую деталь независимо.
4. **Аксессуары** — отдельные предметы, перетаскивание/поворот/размер.
5. **Готово** — помещает персонажа в коллекцию текущей сессии.

**Первое использование:** сразу готовый шарик с глазами. После выбора флага никаких других обязательных шагов. У каждого раздела крупная иконка, изменения видны немедленно, действие «Назад» не сбрасывает уже сделанное.

### 3.3. Экран сцены

- Фон занимает игровую область; коллекция созданных Countryballs находится в прокручиваемой ленте.
- Персонажа можно добавить на сцену нажатием карточки или перетаскиванием из ленты.
- По умолчанию на сцене 1–5 персонажей; ограничение MVP — **не более 8 одновременно**, чтобы управление не превращалось в беспорядок. Позже лимит параметризовать.
- Один палец/мышь — перетаскивание выбранного персонажа.
- Два пальца на выбранном персонаже — масштабирование и поворот (требуется своя обработка жестов с определением цели).
- На ПК — рамка/угловые маркеры для масштаба и вращения. На сенсорном устройстве — возможность делать то же крупными видимыми ручками как резервный способ управления.
- Одно короткое нажатие выделяет Countryball и показывает панель эмоций/действий.
- Для парного действия: нажать первого → выбрать действие → нажать второго; второй должен заметно подсвечиваться при наведении/касании.
- Нажатие в пустое место снимает выделение и скрывает контекстные элементы.
- **Ручное перемещение всегда имеет приоритет:** прервать или мягко завершить анимацию, если ребёнок начинает тащить персонажа.

### 3.4. Экраны выбора фонов

Первая поставка: **парк**, **детская площадка**, **праздник**. Выбор карточкой-картинкой, без необходимости читать. Фоны статические или с очень деликатной вторичной анимацией; никакой физики по умолчанию. После выбора сцены интерфейс сразу переходит к размещению персонажей.

Следующие наборы: уютная комната, пляж, снег, космос, чистый белый фон.

## 4. Модель Countryball: флаг и многослойный редактор

### 4.1. Визуальная модель

Countryball — **единый корневой объект** `CharacterGroup` с подслоями и вложенными объектами. В сцене перемещается `CharacterGroup` целиком. В мастерской аксессуары редактируются независимо.

**Предлагаемый порядок от заднего плана к переднему:**

```text
CharacterGroup (общие x, y, scale, rotation)
├── backAccessoriesGroup[]         // хвостики, рюкзак за шариком, крылья
├── sphereGroup
│   ├── circularFlagClipGroup       // рисунок флага внутри круглой маски
│   ├── optionalSoftShading         // мягкий объём, если нравится визуально
│   ├── sphereOutline               // контур шарика
│   └── highlight                   // один полупрозрачный блик
├── faceGroup                       // глаза + рот + мимика
│   ├── eyeParts[]                  // возможны зрачки и веки
│   └── mouthParts[]
├── faceAccessoriesGroup[]         // очки, усы и т.п.
├── headAccessoriesGroup[]         // корона, шапка, бант
├── frontAccessoriesGroup[]        // цветок в руке, реквизит спереди
└── effectsGroup                    // временные ❤️ ✨ !? и пр.; не сохраняется в модели
```

**Ключевое отличие «слоя» от «предмета»:** слой — это контейнер/порядок отрисовки, а не слот на один объект. В одном слое хранится **массив экземпляров аксессуаров**. Можно поставить рядом две шапочки, два банта или пару независимых декоративных предметов, если ребёнок этого хочет. Каждый объект имеет собственные `id`, `x/y`, `scale`, `rotation`, `zIndex` и свойства. Предметы одного слоя можно переставлять «вперёд/назад», но интерфейс этой операции можно добавить позднее.

Не стоит вводить жёсткое ограничение «один предмет на один слой». Для MVP допустим мягкий защитный лимит (например, 20 аксессуаров на одного персонажа) как технический параметр, **не обязательное игровое правило**.

### 4.2. Как флаг «натягивается» на шарик

- Основной подход MVP — **плоский рисунок флага, обрезанный по круглой маске**. Это соответствует знакомой стилистике Countryballs.
- Флаг не «кладётся картинкой поверх» в виде прямоугольника: он занимает всю круглую область шарика. Края обрезаются по окружности.
- Сохранить пропорции исходного флага и заполнить круглую область по принципу `cover`, с центрированием. Для сложных композиций предусмотреть индивидуальный `offset`/`scale` для флага, чтобы герб/символ не уходил за край.
- Поверх флага рисовать контур и мягкий блик, который **остаётся на том же месте при смене флага**.
- По умолчанию не делать дорогую сферическую деформацию полос и символов. Она не требуется для MVP, а узнаваемость некоторых флагов может ухудшить.
- Использовать проверенные растровые/векторные изображения из локальных ресурсов: SVG загружается в `Image`/растровый ресурс перед выводом в Canvas (Konva не является универсальным SVG-рендерером).
- Исправлять ошибки изображений через fallback: нейтральный шарик + подпись страны, не аварийно завершать приложение.

### 4.3. Редактирование предметов

Добавление аксессуара:

1. Ребёнок нажимает крупную пиктограмму в палитре.
2. Предмет появляется в предложенном месте на персонаже (шапка сверху, очки у глаз, рюкзак сзади и т.д.).
3. Его можно перетащить, масштабировать и поворачивать.
4. При повторном выборе **такого же** предмета создаётся второй независимый экземпляр (если достигнут лимит, показывается мягкая визуальная подсказка).
5. Выбранный предмет выделяется простой рамкой и имеет крупную кнопку удаления (корзина/крестик), а также команду отмены последнего действия.

**Якоря по умолчанию:** `top`, `face`, `left`, `right`, `back`, `front`. Они нужны для стартового размещения, но не ограничивают свободное перетаскивание. Координаты хранятся **относительно центра и радиуса Countryball**, а не в пикселях экрана.

Примеры: очки находятся в `faceAccessories`, шапка — в `headAccessories`, две средние наклейки — два отдельных объекта в `frontAccessories`. У каждого предмета собственная трансформация.

**Границы:** не обрезать внешние аксессуары круглой маской флага! Маска нужна только для изображения флага/элементов внутри шара. Внешняя шапка может выступать за круг.

### 4.4. Поворот и масштабирование всей страны

- В мастерской трансформируется **выбранный аксессуар**, если он выделен.
- В сцене трансформируется **весь CharacterGroup**: шар, флаг, лицо, шапка и остальное движутся согласованно.
- Поворот персонажа на сцене не должен самопроизвольно обнулять угол его аксессуаров, поскольку их повороты локальны относительно `CharacterGroup`.
- При сериализации в будущем хранить **данные объектов**, а не ссылку на живой Konva Node и не единственную сплющенную картинку.

## 5. Анимация «смотрит по сторонам»: обязательная особенность

Запрошен визуально простой эффект: Countryball **смотрит то налево, то направо**, за счёт **зеркального отражения относительно вертикальной оси** (то есть горизонтального flip: `scaleX = -1` у соответствующей группы).

### 5.1. Главное техническое правило

**Не отражать весь CharacterGroup целиком!** Если зеркалить шар вместе с флагом, надписи, гербы и асимметричные рисунки на нём окажутся неправильно перевёрнутыми. Правильнее зеркалить **`faceGroup`** и, при необходимости, выбранные привязанные к лицу аксессуары. Флаг, контур и блик остаются неизменными. Для очков с текстом/символами разрешить свойство `mirrorWithFace: false`.

### 5.2. Как сделать движение заметным

Простое отражение симметричной пары глаз может быть не видно. Поэтому:

- У глаз должны быть зрачки или взгляд, смещённый по горизонтали.
- При повороте взгляда менять направление смещения зрачков: `left ↔ right`.
- Дополнительно можно едва сместить лицо на ±3–6% радиуса шара и наклонить его на несколько градусов.
- Смена направления — 0,15–0,3 с, с короткой остановкой. Не делать резкого бесконечного мигания/дерганья.
- В idle на сцене: через случайный интервал примерно **4–8 секунд** персонаж может посмотреть в сторону, задержаться на 0,5–1,2 с и вернуться. Интервалы настраиваемы.
- В мастерской — показать кнопку 👀 для воспроизведения эффекта; фоновый idle необязателен.
- Во время перетаскивания, изменения размера и активного взаимодействия idle-анимация останавливается.
- При выборе системного режима уменьшения анимации эффект сокращается либо отключается.

### 5.3. Структура анимации

```text
lookAround(character):
  cancelIdleIfBusy(character)
  face.lookDirection = LEFT
  tweenPupilOffset(-offset, 180ms)
  hold(600ms)
  face.lookDirection = RIGHT
  tweenPupilOffset(+offset, 180ms)
  hold(600ms)
  face.lookDirection = CENTER
  tweenPupilOffset(0, 180ms)
```

Если в реализации действительно требуется зеркалирование `scaleX`, менять его **в локальной группе лица** с правильным `offsetX` в центре, не затрагивая флаг. Убедиться, что смена знака не вызывает исчезновения лица в промежуточном кадре: допустима дискретная смена зеркального направления плюс плавное смещение зрачков.

**Критерий приёмки:** у персонажа с несимметричным флагом (например, с гербом) после анимации остаётся правильный рисунок флага, а глаза заметно смотрят влево и вправо.

## 6. Эмоции, характеры, взаимодействия

### 6.1. Эмоции

Первая версия: **радость, смех, грусть, злость, удивление, смущение**. Нажатие на эмоцию изменяет выражение без обязательной дополнительной анимации. Эффекты вроде сердечек и звёздочек могут включаться на 0,4–1,2 с, но не обязательны для всех эмоций.

**Принцип:** выражение эмоции — временное состояние персонажа, а выбранный в мастерской стиль глаз — его базовый внешний вид. После окончания «поспорить», «помириться» и других действий лицо возвращается к исходному выражению или к осмысленному результирующему состоянию (определяется сценарием действия), не теряя базовый стиль глаз.

### 6.2. Характеры: задел, без усложнения

Характер — необязательный атрибут, выбираемый иконкой: **весёлый, застенчивый, озорной, спокойный**. В MVP характер может менять только визуальный idle или оттенок реакции на действие. Он **не запускает самостоятельно** дружбу/ссоры и не блокирует выбранное ребёнком действие. Не привязывать характер к конкретной стране или национальному стереотипу.

Если объём работ ограничен, UI выбора характера вынести в post-MVP, **но поле `personalityId` в модели заложить сразу**.

### 6.3. Перечень действий MVP

| Действие | Тип | Анимация | Звук | Ориентир по времени |
|---|---|---|---|---|
| 👋 Привет | парное | Оба чуть сближаются и подпрыгивают | два мягких «поп» | ~1 с |
| ❤️ Подружиться | парное | Небольшое сближение, сердечко, улыбки | звонкий chime | ~1,5 с |
| 😂 Смеяться | одиночное или парное | Короткое покачивание и прищур глаз | смешной giggle | ~1–1,5 с |
| 💢 Поспорить | парное | Мягкие покачивания, символы «!?», сердитые лица | комичное бормотание | ~2 с |
| 😤 Обидеться | одиночное | Повернулось лицо, надулся, облачко | «хмф» | ~1 с |
| 🤝 Помириться | парное | Сердитость → улыбки, сердечко | приятный аккорд | ~1,5 с |
| 🎵 Танцевать | одиночное или парное | Покачивание + подпрыгивания + нотки | короткий музыкальный мотив | ~2–3 с |
| 💫 Столкнуться | парное | Мягкое касание, откат, удивление | «боп» | ~1 с |

**На следующий этап:** подарить цветок, показать язык, извиниться, хвастаться, совместно прыгнуть, махать рукой, обняться, бросить мягкий снежок. «Подарок» в MVP необязателен: он потребует отдельного временного реквизита, но **не инвентаря**.

### 6.4. Контракт выполнения анимаций

Каждое действие описывается данными: `id`, `kind: solo|pair`, `duration`, `animationKey`, `soundKey`, `fxKey`, допустимые переходы эмоций, возможно возвращение в исходную позу. Визуальный эффект и звук имеют общее событие запуска, но отдельные подсистемы.

- Персонаж не должен «зависать» в промежуточной позе при прерывании.
- Нельзя навесить десятки анимаций одним быстрым тапом: новые действия для уже занятого персонажа заменяют или ставят в короткую очередь (на MVP лучше **замена**).
- Перед парным действием выделяется цель; нельзя выбрать одного и того же персонажа как обоих участников.
- Если персонажи далеко, допускается небольшая временная анимационная подвижка друг к другу, **без изменения сохранённых/пользовательских координат**. После сценки возвращать их к исходным позициям. Это защищает составленную ребёнком композицию.
- Во время анимации касание персонажа для перетаскивания прерывает действие и передаёт управление ребёнку.
- Никакого реалистичного насилия, пугающих звуков и действий с политическим контекстом.

## 7. Звуковая система и озвучка названий стран

### 7.1. Озвучивание флагов — обязательный функциональный сценарий

**Событие:** ребёнок нажал плитку флага → флаг сразу применился к предпросмотру → произнесено **название страны на русском языке**.

Для каждой записи каталога хранить:

- `nameRu` — что показываем под флагом (например, «США»);
- `spokenNameRu` — что произносим (например, «Соединённые Штаты Америки»);
- `audioKey` — путь/идентификатор предварительно подготовленного звукового файла, если используется.

**Два способа реализации:**

1. **Быстрый прототип:** `window.speechSynthesis` + `SpeechSynthesisUtterance`, `lang = 'ru-RU'`; выбрать доступный голос с `lang` начинающимся на `ru`, обрабатывать позднее появление голосов (`voiceschanged`). При быстром выборе следующего флага прекращать предыдущую речь (`cancel()`), чтобы не накапливать очередь.
2. **Рекомендация для итогового детского MVP/PWA:** заранее подготовить и включить в приложение короткие **аудиофайлы с русскими названиями всех стран**, одной приятной и понятной голосовой манерой. Это даёт предсказуемость произношения и стабильный офлайн-режим. Системный TTS можно оставить fallback в разработке и на случай отсутствующего файла.

**Предпочтительный итог:** локальные звуковые файлы, а не исключительно браузерный TTS. Важнее одинаковая и понятная озвучка, чем минимизация нескольких мегабайт ресурсов.

**Правила управления голосом:**

- При новом флаге предыдущая фраза останавливается, запускается новая; никаких наложений десяти названий.
- Случайное повторное касание не должно создавать несколько одновременных дорожек.
- Повторно нажать тот же флаг — повторить название; кнопка 🔊 — то же действие.
- Озвучка отключается отдельной понятной иконкой в настройках, независимо от музыки и звуков эффектов.
- Если аудио недоступно/заблокировано браузером, выбор флага всё равно работает. Отобразить ненавязчивую визуальную обратную связь; не всплывающее техническое сообщение.
- При смене экрана, сворачивании приложения или выключении звука остановить текущую речь.
- Предусмотреть проверку русских ударений/формулировок для необычных названий перед финальным выпуском.

**Формат:** MP3 — практичный основной формат для широкой совместимости; дополнительно можно рассмотреть WebM/Opus при проверенном покрытии устройств. Предзагрузку всех файлов не требовать при первом открытии; кеширование/предзагрузку организовать так, чтобы после завершения установки и подготовки ресурсов все названия были доступны офлайн.

### 7.2. SFX

Начальный набор: нажатие, выбор флага, надеть предмет, удалить предмет, прыжок, сердечко, смех, спор, обида, примирение, столкновение, танец. Звуки короткие, мягкие, без резких перепадов громкости. Ограничить число одновременно проигрываемых SFX и использовать центральный `AudioManager`.

Фоновая музыка — не обязательна в первом вертикальном срезе. Если добавляется, она должна тихо играть, плавно затухать при озвучке названия, иметь отдельную кнопку отключения. Начало музыки — только после пользовательского взаимодействия согласно политике браузера.

## 8. Игровые сцены и визуальные эффекты

### 8.1. Три стартовых фона

| Фон | Иллюстрация | Специальные эффекты (необязательные) |
|---|---|---|
| Парк | Газон, деревья, облака, солнце | редкая бабочка или листочек |
| Детская площадка | Горка, качели, песочница | статичный мяч на фоне |
| Праздник | Шары, гирлянды, декоративная сцена | конфетти при дружбе или танце |

Фоны не определяют список социальных действий: любое действие доступно на любой сцене. Игрушка должна работать и на чистом фоне.

### 8.2. Минимальный набор универсальных эффектов

`heart`, `star`, `question`, `exclamation`, `angerPuff`, `musicNote`, `confetti`, `impact`. Не все эффекты необходимо рисовать как дорогие particle systems: это могут быть 1–5 SVG/PNG-объектов с анимацией `opacity`, `scale` и `y`.

### 8.3. Зрительное качество

- Стилистика — выразительные, читаемые Countryballs: контур, плоский флаг, заметные белые глаза, небольшой блик.
- Не использовать избыточные фильтры, сложные тени и реалистичные 3D-поверхности.
- Глаза/лицо должны хорошо читаться даже при небольшом размере персонажа на сцене.
- Эффекты не закрывают нижние элементы управления и не мешают перетаскиванию.

## 9. Управление и адаптивность

### 9.1. Ввод

| Действие | Сенсор | Мышь / клавиатура |
|---|---|---|
| Скролл флагов | свайп внутри галереи | колесо / трекпад / полоса прокрутки |
| Выбрать флаг | тап | клик |
| Добавить аксессуар | тап по пиктограмме | клик |
| Переместить объект | удержание и перемещение | drag |
| Изменить размер / повернуть | жест двумя пальцами или большие ручки | Transformer/ручки |
| Выбрать действие | тап по персонажу → иконка | клик → иконка |
| Парное действие | персонаж А → действие → Б | то же |
| Отменить выбор | тап по пустому месту | клик по фону / Esc |

### 9.2. Конфликты жестов: отдельно реализовать и протестировать

- Скролл списка флагов **не должен** перетаскивать Canvas.
- На сцене касание персонажа должно перемещать персонажа, а не прокручивать страницу.
- Два касания по персонажу интерпретируются как трансформация персонажа; два касания по пустому фону **не должны случайно менять персонажа**.
- При начале двухпальцевого жеста завершить однопальцевое перетаскивание без скачка позиции.
- Не допускать системного выделения текста и появления контекстного меню браузера внутри игровой области, но **не запрещать масштабирование/доступность всего документа бездумно**: ограничивать `touch-action` точечно в Canvas-области и тестировать сценарии масштабирования ОС.
- Сцена подстраивается под размер окна с корректным пересчётом координат, а не сохраняет пиксели конкретного планшета.

### 9.3. Ориентация

**Приоритет дизайна:** альбомная ориентация удобнее для сцены, но приложение должно работать в портретной и в десктопном окне. Не полагаться на принудительную блокировку ориентации — она поддерживается не во всех браузерах. При узком окне лента персонажей и действия переезжают вниз, а не скрываются полностью.

### 9.4. Доступность

- Контрастные выделения и большие hit areas.
- Любое действие имеет графический смысл; название страны остаётся текстом на русском.
- Для взрослых/использования ПК: DOM-кнопки имеют `aria-label`, видимый keyboard focus; по возможности навигация по сетке флагов стрелками/Tab.
- Учитывать `prefers-reduced-motion` и доступность настройки громкости.
- Избегать мигающих/стробирующих FX и громких неожиданностей.

## 10. Поставляемая модель данных

Ниже **концептуальные TypeScript-типы**, которые можно уточнять при реализации. Координаты аксессуаров нормализуются относительно радиуса персонажа, а координаты персонажей сцены — относительно логической области сцены, не CSS-пикселей.

```ts
type CountryCode = string; // e.g. "RU", "JP"; curated list, not blind ISO import

type CountryCatalogEntry = {
  code: CountryCode;
  nameRu: string;           // подпись: "США"
  spokenNameRu: string;     // озвучка: "Соединённые Штаты Америки"
  flagAsset: string;        // local resource, e.g. /assets/flags/ru.svg
  flagCrop?: { scale: number; offsetX: number; offsetY: number };
  voiceAsset?: string;      // e.g. /assets/voice/ru.mp3
};

type Transform = {
  x: number;
  y: number;
  scale: number;
  rotationDeg: number;
};

type AccessoryLayer =
  | 'back'
  | 'face'
  | 'head'
  | 'front';

type AccessoryInstance = {
  id: string;               // unique instance ID: duplicates allowed
  assetId: string;          // "crown", "ribbon", "glasses"...
  layer: AccessoryLayer;
  transform: Transform;     // x/y relative to the character radius
  zOrder: number;
  mirrorWithFace?: boolean;
};

type ExpressionId =
  | 'happy' | 'laugh' | 'sad'
  | 'angry' | 'surprised' | 'shy';

type LookDirection = 'left' | 'center' | 'right';

type Character = {
  id: string;
  countryCode: CountryCode;
  eyeStyleId: string;
  baseExpression: ExpressionId;
  personalityId?: 'cheerful' | 'shy' | 'mischievous' | 'calm';
  accessories: AccessoryInstance[];
  // Сессионные transient-поля анимации могут храниться отдельно.
};

type SceneCharacter = {
  instanceId: string;       // один тип Countryball можно создать несколько раз
  characterId: string;
  transform: Transform;     // position in logical scene coordinates
};

type SceneState = {
  backgroundId: string;
  actors: SceneCharacter[];
  selectedInstanceId?: string;
};

type GameSession = {
  characters: Character[];  // только состояние текущей открытой сессии
  scene: SceneState;
  settings: {
    speechEnabled: boolean;
    sfxEnabled: boolean;
    musicEnabled: boolean;
  };
};
```

**Важные разграничения:**

- `CountryCatalogEntry` — справочник, не изменяется игроком.
- `Character` — созданный в мастерской внешний вид персонажа.
- `SceneCharacter` — экземпляр на конкретной сцене, с собственным расположением.
- `AnimationState` — отдельное временное состояние: **не смешивать `idle`/`lookDirection`/`tween` с постоянными данными персонажа**.
- Слой содержит массив `AccessoryInstance[]` (фильтрация по `layer`), а не ровно один аксессуар.
- В будущем `GameSession` можно сериализовать в IndexedDB/localStorage по версии схемы, **но это не задача MVP**.

### 10.1. Структура проекта (вариант)

```text
src/
  app/                 # shell, routes, responsive layout, PWA update UX
  features/
```

## 11. PWA и офлайн-режим

### 11.1. Требования

- Доступ по обычному HTTPS URL, работает в браузере без установки.
- `manifest.webmanifest`: имя на русском, русское краткое имя, иконки (включая 192×192 и 512×512), `start_url`, `display: "standalone"`, цвет темы.
- Service worker кеширует HTML, JS, CSS, PWA-иконки, графику стран, аксессуары, фоновые изображения и SFX. Для полной офлайн-озвучки все 195 голосовых файлов должны быть доступны локально или в заранее наполненном кеше.
- **Офлайн-готовность — проверяемое состояние:** не обещать полный офлайн сразу после первого отображения интерфейса, пока обязательные файлы ещё скачиваются. Можно показать ненавязчивый индикатор/сообщение взрослому после завершения кеширования.
- Базовая функциональность не должна требовать обращения к интернет-API.
- Обновления service worker безопасны: новая версия не должна самопроизвольно перезагрузить игру посреди сценки. Показать обновление на главном экране/при следующем запуске.
- По возможности не закреплять ориентацию. Поддерживать landscape и portrait через адаптивный CSS.
- Поддержать браузерное открытие даже там, где установку PWA конкретный браузер не предлагает.

### 11.2. Что не считать сохранением

Кеш ассетов служит для офлайн-работы PWA; это **не хранилище персонажей и сцен**. Пользовательские творения в MVP могут исчезнуть при закрытии/перезагрузке страницы. После проработки концепции запланировать сохранение отдельно, прежде чем игра станет основным постоянным развлечением ребёнка.

## 12. Каталог ассетов и лицензии

Нужен единый визуальный стиль и предсказуемые размеры/якоря ассетов.

**Минимальные ассеты:**

- Флаги для всех записей каталога (локальные SVG/PNG, корректный код и ориентация).
- Базовый шарик: контур + блик, прозрачная графика или рендер геометрией.
- 6 шаблонов глаз и согласованные мимические комбинации.
- 10–15 аксессуаров: корона, кепка, шапка, бантик, обычные очки, солнечные очки, усы, цветок, наушники, рюкзак, волшебная палочка и др.
- 3 фона.
- 8–12 SFX/коротких музыкальных акцентов.
- Набор иконок действий и временных FX.
- Озвучка русских названий (195 коротких файлов) для итогового стабильного MVP.

**Юридическая/качественная проверка:** флаги как символы и конкретные SVG-файлы из библиотек — не одно и то же с точки зрения условий использования. Выбрать источник с подходящей лицензией, сохранить атрибуции при необходимости. Не копировать исходные изображения глаз, аксессуаров и фонов из существующей игры без разрешения. Использовать собственные или надлежаще лицензированные иллюстрации и звуки.

## 15. Основные риски и способы снизить их

| Риск | Меры |
|---|---|
| Слишком сложная мастерская | 4 основные вкладки, крупные иконки; не показывать разработческие понятия «слой», `zIndex`, `transform` ребёнку |
| Непоследовательное изображение флагов | Единый проверенный каталог, отдельные crop-поправки для сложных флагов |
| «Отражение» портит флаги | Зеркалить только `faceGroup`; тестировать асимметричные флаги |
| Не слышно озвучки на одном из устройств | Подготовленные локальные аудиофайлы, явная кнопка повтора, проверка блокировки autoplay |
| TTS работает только онлайн / произносит неправильно | TTS для прототипа, заранее записанная русская озвучка для итогового релиза |
| Жесты конфликтуют со скроллом и друг с другом | Разделить DOM-галерею и Konva-сцену; централизованный gesture controller; тесты multitouch |
| Персонаж случайно испорчен детскими жестами | Undo, понятное выделение и удаление, разумные bounds на размеры |
| Разросшийся масштаб MVP | Сначала 3 фона, 8 действий, 10–15 аксессуаров; никакой сложной автономной логики |
| PWA не работает офлайн сразу | Явная стратегия полного предварительного кеширования и тест «авиарежим» |
| Потребление памяти на экране высокого разрешения | Минимум canvas layers, профилирование DPR/кеширования, пауза невидимых анимаций |
| Потеря созданных персонажей при перезагрузке | Явно принять как ограничение прототипа; добавить полноценное сохранение следующим этапом |

## 17. Инструкции для первого Codex-чата

**Цель:** реализовать проект инкрементально на базе этого документа, начав с вертикального среза, а не пытаясь сразу сделать все функции.

### Рекомендуемый стартовый срез

1. Vite + React + TS + react-konva + PWA shell.
2. Небольшой демонстрационный каталог (10–15 стран) с русскими подписями — пока не импортировать вслепую весь мир.
3. При нажатии на флаг — шарик с круглой маской и голосовым произношением выбранной страны (на прототипе допустим Web Speech API).

5. Сделать `lookAround`: зеркалирование/смещение лица, не флага.
6. Два созданных персонажа на сцене «Парк», с перетаскиванием и действием «Поздороваться».

### Инженерные требования к реализации

- Разделять доменные данные персонажа и визуальные узлы Canvas.
- Не привязывать координаты к конкретной модели/разрешению планшета.
- Не делать пользователей и сервер до появления реального требования.
- Не копировать ассеты из существующей Countryballs-игры без прав.
- Написать минимум тестов из раздела 14, особенно C03, C07–C10, C13, C14, C18 и C24.
- После каждого milestone запускать рабочую демонстрацию и исправлять UX, а не только писать отчёт.
- При конфликте между количеством функций и простотой для ребёнка выбирать **простоту**.

### Definition of Done для общего MVP

- [ ] PWA открывается из браузера и может работать офлайн после кеширования.
- [ ] У ребёнка есть единый каталог из 195 флагов и русских названий, без континентального меню.
- [ ] При нажатии на любой флаг звучит его название по-русски; повтор и mute работают.
- [ ] Флаг корректно заполняет круглый шар, а не отображается прямоугольной наклейкой.
- [ ] Глаза/мимика/аксессуары — независимые редактируемые элементы.
- [ ] В одном визуальном слое могут находиться два и более предмета.
- [ ] Countryballs умеют заметно смотреть по сторонам, при этом флаги не переворачиваются зеркально.
- [ ] Можно создать нескольких персонажей и собрать их на одной сцене.
- [ ] Работают три фона, ручное перемещение, масштаб/поворот, простые эмоции и 8 действий со звуком.
- [ ] Игра не требует чтения длинных инструкций, регистрации, карты, заданий или сервера.
- [ ] Проведена хотя бы одна реальная игровая сессия с ребёнком и внесены исправления UX.

**Главная метрика успешности:** ребёнок может самостоятельно и с удовольствием создавать Countryballs и разыгрывать с ними сценки. Остальные метрики вторичны.
